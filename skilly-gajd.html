Теория

Что такое скилл?

Из чего состоит и как работает
Скилл – это файл с инструкцией для Claude Code Markdown-файл (.md) с системным промптом, который запускается командой /имя прямо в разговоре. Никаких проектов – одна команда, и эксперт уже в чате.

Из чего состоит скилл

Файл .md
Обычный Markdown-файл в папке .claude/skills/. Название файла = команда запуска.
Системный промпт
Роль, инструкции, формат ответа, ограничения. Все в одном файле – как Project Instructions, но компактнее.
Метаданные (опционально)
Описание скилла, автор, версия. Помогают при публикации и поиске.
Зависимости (опционально)
Скилл может вызывать другие скиллы или использовать MCP-коннекторы.
# Пример структуры скилла (файл: продавец.md)

---
name: Универсальный Продавец
description: Квалифицирует лидов и закрывает возражения
---

# Роль и задача
Ты – эксперт по продажам. Твоя задача...

# Инструкции
1. Сначала задай квалификационные вопросы...
2. Работай с возражениями через формулу...
Запуск одной командой Набираешь /продавец в любом чате Claude Code – скилл активируется мгновенно. Без настройки, без проекта.

Теория

MCP-коннекторы

Model Context Protocol – мост между Claude и внешними сервисами
Что такое MCP? Model Context Protocol – стандарт от Anthropic. Позволяет Claude напрямую работать с внешними сервисами: читать Notion, пушить в GitHub, отправлять сообщения. Не через копирование – через живое подключение.
Notion MCP
Claude читает и пишет в твои базы Notion напрямую. Задача = "добавь задачу в трекер" → Notion обновляется автоматически.
GitHub MCP
Claude создает issues, пишет код и делает pull requests прямо в репозиторий. Без копирования туда-обратно.

Как установить MCP-коннектор

Найди коннектор – в Claude Code меню или на сайте
Официальные: smithery.ai – там каталог MCP-серверов с рейтингом.
В Claude Code: Settings → MCP → Add Server
Вставь команду установки из документации коннектора.
Авторизуй доступ к сервису (Notion / GitHub)
Откроется OAuth – залогинься в нужный сервис и дай разрешение.
Скажи Claude: "Добавь задачу в мой Notion"
Claude сам использует коннектор – не нужно ничего настраивать дополнительно.
MCP – это расширение скилла Скилл + MCP-коннектор = скилл, который не просто отвечает, а делает реальные действия во внешних сервисах. Это уже территория агентов – но начинается здесь.

Плагины

Несколько скиллов в одном – организованная система
Плагин – это пакет скиллов Если скилл – один специалист, то плагин – это целый отдел. Несколько связанных скиллов, объединенных под общим названием с единой логикой запуска.
Скилл
Один файл → одна задача

Пример: /продавец – квалифицирует лида
Плагин
Пакет скиллов → система задач

Пример: Direct Funnel – весь цикл воронки в одном плагине
Пример: плагин Direct Funnel
Один плагин включает несколько скиллов, которые работают вместе:
/funnel-research
Анализ аудитории и болей
/funnel-offer
Создание оффера по методологии
/funnel-sequence

Скилл vs Claude Project

Когда что использовать
ПараметрСкиллClaude Project

Практика

Как устанавливать скиллы

Три способа – от простого к ручному
Способ 1 – Ссылка
Получаешь ссылку на скилл (GitHub / сайт). Claude Code устанавливает автоматически через /install.
Способ 2 – Файл
Скачиваешь .md файл → кладешь в папку .claude/skills/ вручную.
Способ 3 – Копипаст
Копируешь текст промпта → создаешь файл вручную с нужным именем.

Установка через сайт виртуальных сотрудников

Открой virtual-employees-personal.vercel.app
Каталог всех доступных скиллов – выбирай нужный.
Нажми на скилл → вкладка "Instructions"
Там полный текст промпта. Нажми "Copy" или "Download .txt".
Создай файл имя-скилла.md в папке .claude/skills/
Вставь скопированный текст. Имя файла = команда запуска.
В Claude Code набери /имя-скилла – готово
Скилл активируется мгновенно. Никакого перезапуска не нужно.

Практика

Локальные vs Облачные скиллы

Чем отличаются и что выбрать
Локальные скиллы
Хранятся на твоем компьютере в папке .claude/skills/

Плюсы: работают без интернета, видишь код, полный контроль

Минусы: только на этом компьютере, надо передавать файлами
Облачные скиллы
Хранятся на GitHub или другом хостинге, устанавливаются по ссылке

Плюсы: легко делиться, всегда актуальная версия, один клик

Минусы: нужен интернет, чужой код – надо проверять
Практика Свои рабочие скиллы держи локально. Проверенные скиллы сообщества – ставь по ссылке. Новые незнакомые – сначала читай код, потом устанавливай.

Практика

Как создать свой скилл

От идеи до рабочего файла
Лучший первый скилл – тот, который делаешь уже сейчас руками Что ты объясняешь Claude снова и снова? Это и есть задача для скилла. Упакуй один раз – пользуйся всегда.
Найди повторяющуюся задачу
Что ты делаешь через Claude чаще 3 раз в неделю? То и упаковывай.
Напиши промпт с ролью, задачей и форматом
Роль → что делает. Задача → алгоритм. Формат → как выглядит ответ. Примеры – обязательно.
Создай файл мой-скилл.md в .claude/skills/
Добавь метаданные: name, description – пригодится при публикации.
Протестируй на 10 разных кейсах
Хороший скилл стабилен – на простых и сложных задачах результат одинаково качественный.
Доработай по итогам – и скилл готов
Это актив. Его можно улучшать, отдавать команде, продавать, публиковать.

Скилл, который создает другие скиллы

Что умеет

  • Добавляет метаданные и документацию

3. Опиши задачу своими словами

GitHub – публикация и шеринг

Как поделиться скиллом с командой или сообществом
Создай репозиторий на github.com
Назови понятно: my-claude-skills или ai-skills-marketing. Сделай публичным.
Загрузи .md файлы скиллов
Каждый скилл – отдельный файл. Добавь README с описанием что и как устанавливать.
Скопируй ссылку на файл (Raw)
На GitHub: открой файл → кнопка "Raw" → скопируй URL. Это и есть ссылка для установки.

Обновления автоматически Если скилл установлен по GitHub-ссылке – при обновлении файла в репозитории все установившие получат новую версию при следующем использовании.

Важно

Безопасность при работе со скиллами

Два риска: утечка твоих данных и чужой вредоносный код
Два вектора угроз 1. Ты создаешь скилл и случайно вшиваешь туда личные данные.
2. Ты устанавливаешь чужой скилл – а там вредоносный код или инструкции слить данные.

Когда создаешь скилл – не включай это

API-ключи и пароли
Никогда не вставляй в текст скилла токены, ключи, пароли. Скилл – публичный файл, он может уйти куда угодно.
Личные данные клиентов
Имена, телефоны, данные сделок – не в промпте. Это не должно быть в файле скилла никогда.
Конфиденциальные данные компании
Финансовые показатели, внутренние процессы, стратегия – только если скилл приватный и только для себя.

Когда устанавливаешь чужой скилл – проверь это

Всегда читай код перед установкой
Скилл – это просто текстовый файл. Открой, прочитай. Если там инструкции "отправь данные на адрес..." – это атака. Удаляй.
Устанавливай только из известных источников
Каталог курса, smithery.ai, крупные GitHub-репозитории с историей и звездами. Незнакомый Telegram-бот с файлом – красный флаг.
Следи за правами MCP-коннекторов
При установке MCP сервис запрашивает доступ. Давай только то, что нужно для работы. Коннектор к Notion не должен просить доступ к контактам или файловой системе.
Удаляй скиллы, которые не используешь
Неиспользуемый установленный скилл – потенциальная дыра. Папку .claude/skills/ нужно периодически чистить.
Простое правило безопасности Скилл – это инструкция, не программа. Он не может сам по себе отправить данные или запустить вирус. Но содержимое может заставить Claude сделать что-то вредное. Поэтому – читай перед установкой, не включай секреты при создании.
